# Configuration

<sub>[← Back to README](../README.md)</sub>

All configuration lives in `.env` (copy `.env.example` to start). Every
key below is read once, at process start, by `app/config/` (Pydantic
settings) — changing `.env` requires a process restart.

## Core variables

| Variable | Purpose | Notes |
|---|---|---|
| `LLM_MODEL` | Ollama model tag used for generation | Must already be pulled (`ollama pull <tag>`) |
| `EMBEDDING_MODEL` | Multilingual embedding model for dense retrieval | See RAM note below before changing |
| `RERANKER_MODEL` | Cross-encoder used to rerank hybrid results | Sigmoid-normalized output, see [`hybrid-retrieval.md`](hybrid-retrieval.md) |
| `CHUNK_SIZE` / `CHUNK_OVERLAP` | Text splitting parameters | Only applies to articles exceeding the legal-structure chunk boundary |
| `TOP_K` / `RERANK_TOP_K` | Candidates before/after reranking | `TOP_K` per engine (dense + sparse) before fusion; `RERANK_TOP_K` after reranking |
| `DENSE_WEIGHT` / `SPARSE_WEIGHT` | Hybrid score fusion weights | Applied to the min-max *normalized* scores, not raw ones |
| `VECTOR_PATH` / `BM25_PATH` / `SQLITE_PATH` | Where indexes/metadata are stored | Regenerated by the indexing pipeline — safe to delete to force a full rebuild |
| `MAX_CONTEXT_CHARS` | Context compression budget | Caps prompt size after dedup |
| `LOG_LEVEL` | Logging verbosity | Every stage logs through `app/utils/logger.py` to `logs/app.log` and stdout |

## RAM and the embedding model

The project's original design spec named `BAAI/bge-m3` (~2.3GB of
weights, roughly double that in RAM transiently while loading) as the
example embedding model. On an 8GB-RAM machine, loading `bge-m3` hung
indefinitely on `EMBEDDING_DEVICE=mps` and thrashed (severe swapping,
10+ minutes without completing) on `EMBEDDING_DEVICE=cpu` — a resource
constraint, not a bug.

Because of that, **the default `EMBEDDING_MODEL` is the much lighter
`sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`
(~470MB)**, which loads quickly and correctly on constrained hardware
and is what the test suite uses. If you have more RAM headroom (16GB+
recommended) and want better retrieval quality (particularly on Uzbek's
rich morphology — see [`hybrid-retrieval.md`](hybrid-retrieval.md)),
switch to `BAAI/bge-m3` or `intfloat/multilingual-e5-large` — both are
fully supported. If a heavier model hangs or thrashes:

- Close other memory-heavy applications before the first load.
- Prefer `EMBEDDING_DEVICE=cpu` over `mps` — `mps` produced an outright
  hang in testing; `cpu` at least made (slow) forward progress.
- `intfloat/multilingual-e5-base` (~1.1GB) is a reasonable middle ground.

## Frontend configuration

The Next.js frontend reads its own `frontend/.env.local` (copy from
`.env.local.example`):

| Variable | Purpose |
|---|---|
| `NEXT_PUBLIC_API_URL` | FastAPI backend URL (default `http://localhost:8000`) |
| `NEXT_PUBLIC_STREAMLIT_URL` | Streamlit debug tool URL, for the navbar's Settings deep-link (default `http://localhost:8501`) |
| `NEXT_PUBLIC_GITHUB_URL` | Optional — shows a GitHub navbar button when set |
